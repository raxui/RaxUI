# ADR 014 — Icons: Lucide in both frameworks

- **Status:** Accepted
- **Date:** 2026-10-24

## Context

Components need a few icons of their own (close, check, chevron, calendar, clock, eye, search, upload), and apps put their own icons into component slots (Button content, input start/end slots). boot-ui ships no icon library: its icons are inline SVG and its slots take any node. Font Awesome was considered and excluded by the owner: the CSS variant loads the whole font, and its outline style does not match boot-ui's stroke icons.

Blazor has no official Lucide package. Candidates checked on 2026-10-24: `Blazicons.Lucide` 3.1.10 (MIT, on `Blazicons` 4.0.21, MIT; net6.0/net8.0/net10.0 assets, net9.0 uses net8.0; active), `BlazorBlueprint.Icons.Lucide` 2.0.2 (MIT, net8.0), and smaller packages.

## Decision

- **Icon set:** [Lucide](https://lucide.dev) (ISC) in both frameworks, so both look the same and match boot-ui's 2px stroke icons.
- **SheenUI's own icons** are inline SVG in the component source, with `stroke="currentColor"` and `aria-hidden="true"`. No icon dependency is installed with any component. Paths copied from Lucide keep a one-line ISC notice in the file.
- **App icons** are the developer's choice; slots accept any markup (`RenderFragment` in Blazor, `ReactNode` in React). The documented recommendation:
  - React: `lucide-react` (1.61.0 when checked).
  - Blazor: `Blazicons.Lucide` 3.1.10, as `<Blazicon Svg="Lucide.Mail" aria-hidden="true" />`.
- **Slot styling contract:** icons inherit color through `currentColor` and are sized by the slot. Slot rules use two classes (for example `.btn-glass.btn svg`) so a library's own sizing does not win. `Blazicons` adds `svg[blazicon] { width: 1em; height: 1em }` in the app's `styles.css`, which loads after `sheenui.css`.

## Verification of Blazicons.Lucide

Real Blazor Web Apps on .NET 8, 9, and 10 (Interactive Server), with `sheenui init`, `sheenui add button`, and `Blazicons.Lucide` 3.1.10, built with 0 warnings and 0 errors. In Chromium:

- Static SSR and interactive pages render the SVG with `stroke="currentColor"` and inherit the text color, including white inside a primary Button.
- The size is 1em, or the slot's size: 18px (1.125em) inside Button after the two-class rule above, 16px before it.
- Extra attributes (`aria-hidden`, `class`) are passed through to the `<svg>`.
- An interactive page swaps `Lucide.Eye` and `Lucide.EyeOff` on click.
- No console errors.

Icon names follow Lucide's current set as generated by the package (for example `Lucide.Trash`; there is no `Trash2` in 3.1.10).

## Alternatives Considered

- **Font Awesome:** excluded by the owner (see Context).
- **Bootstrap Icons:** close to Bootstrap's look, but in Blazor usually loaded as a font (the same size cost), and less consistent with boot-ui's icons.
- **A SheenUI icon package:** more to maintain than inline SVG for the few icons components need; apps already have good Lucide packages.

## Consequences

- Components stay dependency-free for icons; apps add one package if they want Lucide everywhere.
- New slot styles must follow the two-class sizing rule and be checked with a Blazicons icon.
- `aria-hidden` is not added by Blazicons automatically; the docs show it on decorative icons.
