# ADR 009 — Blazor on .NET 8, 9, and 10

- **Status:** Accepted
- **Date:** 2026-10-23
- **Supersedes:** The single .NET 10 target in [ADR 002](002-first-milestone-scope.md) and [ADR 004](004-simplified-first-milestone.md).

## Context

The first milestone targeted only .NET 10. Many Blazor apps still run on .NET 8 (LTS) and .NET 9. The templates differ:

| | .NET 8 | .NET 9 | .NET 10 |
| --- | --- | --- | --- |
| Bootstrap | 5.1.0 in `wwwroot/bootstrap/` | 5.3.3 in `wwwroot/lib/bootstrap/` | 5.3.3 in `wwwroot/lib/bootstrap/` |
| Static asset links | plain URLs (`UseStaticFiles`) | `@Assets[...]` (`MapStaticAssets`) | `@Assets[...]` |
| Layout and sample pages | own versions | own versions | own versions |

The theme needs Bootstrap 5.3: `data-bs-theme` for dark mode and the `--bs-btn-*` variables the Button styles set.

## Decision

- **Targets:** Blazor Web Apps on `net8.0`, `net9.0`, and `net10.0`, read from the evaluated `TargetFramework`. Multi-targeted projects and other frameworks are rejected with a clear error. `sheenui.json` records the detected target.
- **The CLI runs on any of them:** `SheenUI.Cli` targets `net8.0;net9.0;net10.0`, so a machine with only the .NET 8 SDK can run it. Code avoids APIs newer than .NET 8.
- **Bootstrap:** `init` finds the template Bootstrap in either folder. When it is the unmodified .NET 8 template file (Bootstrap 5.1), `init` replaces it in place with Bootstrap 5.3.8 bundled in the CLI (MIT license header kept) and tracks it in the lock like other assets; `App.razor` keeps its link. Any other Bootstrap older than 5.3 stops `init` with instructions. Unrecognized or newer files are left alone.
- **Links:** `init` writes `@Assets["css/sheenui/sheenui.css"]` on .NET 9 and 10, and `css/sheenui/sheenui.css` on .NET 8, matching each template.
- **Starter:** the template fingerprints of .NET 8 and 9 (with and without interactivity) join those of .NET 10 ([ADR 008](008-starter-app.md)). The starter layout and welcome page compile on all three (C# 12, `[SupplyParameterFromQuery]` on any component since .NET 8).

## Alternatives Considered

- **Stop on .NET 8 and ask the developer to upgrade Bootstrap:** Every .NET 8 user would hit a manual step on a supported target.
- **Ship our own Bootstrap and change the `App.razor` link:** More host edits than replacing the unmodified template file in place.
- **Require the .NET 10 SDK to run the CLI:** Excludes developers who only have the SDK their app uses.

## Consequences

- CI installs the .NET 8, 9, and 10 SDKs and runs the real-app test on each target.
- The CLI package carries Bootstrap 5.3 CSS (about 230 KB), used only for .NET 8 template upgrades.
- A Bootstrap upgraded by `init` is a SheenUI-tracked file: editing it makes later `init` runs refuse to overwrite it, like other tracked assets.
